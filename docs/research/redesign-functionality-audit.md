# Kingdra redesign: functionality, Showdown parity, and design references

Researched 2026-10-08 against local commit `2d7533756934dba995dde16ee7ee436548074538` and first-party upstream source. This is the canonical research note for the redesign. No application code was changed. No existing research directory convention preceded this work; research is now kept in `docs/research`.

The current app is a useful six-member team editor, but it does **not** have complete Pokémon Showdown teambuilder parity. A redesign must preserve its supported interactions while repairing data loss and generation errors, then add the agreed set fields, standard-format rules, library operations, and lossless text import/export. “Preserve” below means preserve the user capability, not preserve a known defect or the old screen arrangement. The later interview narrows the original full-parity request: custom formats, Undo, format-aware suggested movesets, external publication and Showdown account integration are excluded; PC-style storage boxes are a deferred stretch goal.

## Scope and evidence

- Existing behavior is established from the complete `src/app`, `src/components`, `src/lib`, and `src/pages/api` source tree. Sources are linked to exact local starting lines. Static defects are identified separately from supported behavior; they have not all been reproduced interactively.
- Root-agent live inspection at roughly 667 px confirmed six blank slots, Add Pokémon, team Import/Export, and a hamburger; the add dialog contains Gen 9, OU, and search controls. That is supplementary evidence; source is the authority for capability coverage.
- No applicable `AGENTS.md` was found in this repository or its ancestor directories. Existing README claims are not accepted as implementation evidence where source contradicts them.
- Upstream research uses the official Smogon Showdown simulator and client repositories. The maintained client includes both a newer Preact editor and an `oldclient` implementation; source availability does not prove a feature is already live on every Showdown client variant. Upstream links point to moving `master`; freeze a revision when implementing parity.
- **Teambuilder** editing is the user-confirmed scope, subject to the later explicit exceptions recorded above and in Q40–Q41. Battle simulation, multiplayer battling, ladder, chat, replay, and tournament operation are outside this redesign. Parsing, standard-format validation, and set stat calculation are teambuilder concerns and may use simulator libraries without building a battle UI.

## Pokémon Showdown parity: primary-source findings

### Set model and serialization

Showdown separates nickname `name` from `species` including forme. Its set schema includes item, ability, moves, nature, gender, six EVs/IVs, level, shiny, happiness, Poké Ball, Hidden Power type, Dynamax level, Gigantamax, and Tera type. IVs also represent early-generation DVs; EV storage also supports Let's Go AVs and Champions points. Poké Ball has an explicit TODO for validator/teambuilder support, so model/round-trip support is distinguishable from editable live-client parity. Import accepts text, packed and JSON; export preserves relevant optional fields. **Required additions:** separate nickname/species, every missing field, canonical normalization, and lossless set/team round-trip. [Official set schema and serializers](https://github.com/smogon/pokemon-showdown/blob/master/sim/teams.ts#L18)

### Editor capabilities and conditional details

Maintained client source supports species/form replacement, nickname, item/ability/move editing, set copy/move/paste, delete/undo, base/final stat bars, nature, spread guessing/optimization, automatic/low-Atk/low-Speed IV choices and Hidden Power-aware IVs. Stats adapt to Gen 1–2 DVs, Let's Go AVs (200 per stat), Champions points (32 per stat/66 total, IVs hidden), and mainline EVs (510 total; efficient remainder can display 508). Details include gender, shiny, happiness where relevant, Gen 8 Dynamax level/Gmax, and conditional Tera. Editor format selects the modded dex. **Design implication:** Stats and Details need format-aware variants and spread tools. The user expressly excludes Undo; upstream Undo is documented for research completeness, not added to this design. [Official extracted editor](https://github.com/smogon/pokemon-showdown-client/blob/master/play.pokemonshowdown.com/src/battle-team-editor.tsx#L35)

### Formats and legality

Formats encode generation/mod, Singles/Doubles and other game types, rulesets, inherited bans, level/team/move limits, and custom rules. UU inherits OU then additionally bans OU/UUBL; RU inherits UU then bans UU/RUBL. Thus sorting a tier ceiling alone is insufficient. Current Gen 9 Custom Game declares 24 team members, 24 moves, level 9999; those are exceptions to the standard six-member/four-move/1–100 design. The config also includes National Dex, Let's Go and Champions variants. **Design implication:** make the team's actual standard format authoritative and the carousel tier/gen filters a subset of that context. Q12 explicitly excludes custom formats and their exceptional limits. [Official formats](https://github.com/smogon/pokemon-showdown/blob/master/config/formats.ts#L71)

Validator checks are generation/rule-aware across species, formes, moves, item/ability/nature, EV budget, level, source/event/transfer compatibility, gender/shiny and Hidden Power/DVs; validation can adjust sets. Early generations share Special and derive HP DV; Gen 2 shininess/gender depend on DVs. Hyper Training affects Hidden Power compatibility. **Required addition:** a Validate result with actionable field-specific issues, run against selected format; simple per-field ranges or usage statistics cannot substitute. Preserve original user input while showing any normalized/adjusted result. [Official validator](https://github.com/smogon/pokemon-showdown/blob/master/sim/team-validator.ts#L1094), [Official configurable limit rules](https://github.com/smogon/pokemon-showdown/blob/master/data/rulesets.ts#L2069)

### Search and library parity

Showdown's search source is format/set aware and contains Pokémon, moves, item and ability search, filtering/sorting and legality-aware result categories. Result rows include species types/abilities/base stats and move power/accuracy/PP/category/descriptions. **Required addition:** catalogue-wide search, informative role/type cards, contextual field search and format-aware availability; role labels must specify whether curated or inferred from the current set. Existing usage lists are insufficient.
