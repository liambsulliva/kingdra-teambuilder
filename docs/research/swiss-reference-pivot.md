## Exact subpage menu hover

The requested moving subpage glyph is **CompactNavIcon**, not lobby **NavLink**. Source structure places CompactNavIcon in `SubpageHeader`'s `compact-nav`, desktop only; the architecture explicitly scopes the scare-bounce to this menu. [SubpageHeader:29](/Users/liambsulliva/Developer/personal-website-v3/src/components/chrome/SubpageHeader.astro:29), [motion contract:484](/Users/liambsulliva/Developer/personal-website-v3/docs/v3-architecture-delta.md:484).

The implemented `scare-bounce` is **420 ms** with the following translate-Y frames: **0%: 0 px; 28%: −7 px; 62%: +1.5 px; 80%: −1 px; 100%: 0 px**. The upward segment uses `cubic-bezier(0.22,1,0.36,1)`; falling uses `cubic-bezier(0.55,0,1,0.45)`; settling uses `ease-out`. The animation runs on hover with `both` fill only when `hover:hover`, `pointer:fine`, and minimum viewport width 768 px match. It animates the glyph inside its hit target. [Exact keyframes:48](/Users/liambsulliva/Developer/personal-website-v3/src/components/chrome/CompactNavIcon.astro:48).

CompactNavIcon uses a **36 px hit target, 24 px glyph**, and a **13 px medium** section label 4 px below the hit. Label opacity fades using the 150 ms fast motion token and ease-out; hover and keyboard focus reveal the label, while the bounce trigger itself is hover only. [Geometry and label:18](/Users/liambsulliva/Developer/personal-website-v3/src/components/chrome/CompactNavIcon.astro:18), [label behavior:34](/Users/liambsulliva/Developer/personal-website-v3/src/components/chrome/CompactNavIcon.astro:34), [fast token:61](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:61).

NavLink's actual hover treatment is underline; its press-scale comes from `.squishy`. It does not use the scare-bounce. [NavLink:92](/Users/liambsulliva/Developer/personal-website-v3/src/components/chrome/NavLink.astro:92). Global reduced-motion handling cancels all CSS transitions/animations. [global.css:107](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:107).

## Swiss visual conventions in implementation

The palette uses pure white/black as light background/text, muted text `#3a3a3a`, border and skeleton `#cccccc`, pale card `#f0f0f0`, and surface `#eaeaea`. Dark switches to background `#0f0f0f`, white text, muted `#b5b5b5`, border `#333333`, card/surface `#151515`, skeleton `#262626`. Section accents are semantic colors rather than whole-page saturated backgrounds, with matching softer dark values. [Light tokens:30](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:30), [dark tokens:67](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:67).

Typography in the inspiration site is Geist Sans in weights 400/500/600/700, with Martian Mono Variable for monospace. The body is 16 px / 1.5. Spacing tokens are **4, 8, 12, 16, 24, 32, 48, 64 px**. Radii are **4 px controls, 8 px medium, 12 px cards, 15 px pills**. [Font imports:3](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:3), [font tokens:115](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:115), [spacing/radii:140](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:140), [body:167](/Users/liambsulliva/Developer/personal-website-v3/src/styles/global.css:167). For Kingdra, the user has explicitly approved **Stack Sans** to replace the original UDKakuGo request. [index.astro:34](/Users/liambsulliva/Developer/personal-website-v3/src/pages/index.astro:34), [responsive unit:71](/Users/liambsulliva/Developer/personal-website-v3/src/pages/index.astro:71). ## Application to Kingdra — design inference

The latest refinement replaces compact front sprites with PokeAPI Generation VIII icon assets. Team clusters, deck slots, carousel entries, comparisons and every other compact Pokémon reference use a uniform **48 × 48** image box, with Blastoise as the visual size reference. Compact Pokémon wrappers carry no external padding; cluster and deck icons use 2 px gaps. The deck is pinned to the bottom-left of the central workspace. The shared IconButton is **16 × 16**, with fixed black glyphs and no colored state background. Only the expanded work-desk view retains the full front sprite. General highlights use **#E7E9E8**; **#E8F3FE** and **#3983F7** remain available for icon-specific treatments outside IconButton. Type/stat colors and raster Pokémon colors remain intact.

Use the latest notebook as the region/composition authority and the personal site as the source for spacing discipline, neutral surfaces, type hierarchy, small glyph treatments and motion. Keep team groups as compact six-member 3 × 2 sprite grids; do not reinterpret them as decorative full-size nested cards. Apply the exact CompactNavIcon bounce to tiny Pokemon glyphs while keeping a stable accessible hit region. Build duplicate/delete/import/export as restrained icon controls with tooltips. Keep Pokemon-type and fixed stat-identity color coding as localized information accents, and leave clear negative space around the central selected Pokemon. These are proposed translations of the supplied requirements and inspected reference, not claims that the personal site already has Pokemon components.
